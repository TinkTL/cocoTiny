# 支付宝电脑网站支付生产小额联调设计

日期：2026-07-23

## 目标

在 `www.cocotiny.com` 上使用已经开通的支付宝电脑网站支付能力完成一笔人民币 0.10 元的真实交易，验证应用密钥、签名、支付宝收银台跳转、同步返回、异步通知和主动查单链路。

本阶段只验证支付接口，不交付正式订单持久化、退款、资产授权或下载权限。

## 方案选择

采用最小生产联调方案：

- 创建支付时调用电脑网站支付接口 `alipay.trade.page.pay`。
- 浏览器跳转支付宝收银台，不再生成当面付二维码。
- 支付完成后返回 `/payment/result`。
- 结果页通过服务端主动调用 `alipay.trade.query` 获取权威交易状态。
- 异步通知继续执行 RSA2 验签及应用、商户、金额、订单号和交易状态校验。
- 本阶段不依赖 Vercel 进程内 `Map` 判断支付结果。

不采用现有 `alipay.trade.precreate`，因为它属于当面付产品，与已经开通的电脑网站支付能力不匹配。

## 组件与职责

### 支付创建接口

`POST /api/payments/alipay/create`

- 只接受服务器产品目录中存在的资产包标识。
- 价格由服务器固定为 0.10 元，不接受客户端价格。
- 生成唯一商户订单号。
- 调用 `alipay.trade.page.pay`，传入 `FAST_INSTANT_TRADE_PAY`、异步通知地址和同步返回地址。
- 返回支付宝收银台跳转地址或可提交的支付表单。
- 不把应用私钥或支付宝公钥返回浏览器。

### 支付按钮

- 用户点击后请求支付创建接口。
- 创建成功后跳转支付宝收银台。
- 请求期间禁止重复点击并显示加载状态。
- 创建失败时显示可理解的错误，不暴露密钥、签名或完整支付宝响应。

### 支付结果页

`/payment/result`

- 从支付宝同步返回参数中读取商户订单号。
- 调用本站服务端查询接口，不在浏览器中直接判断支付成功。
- 展示成功、处理中、关闭或失败状态。
- 同步返回仅用于用户体验，不能作为资产交付依据。

### 主动查单接口

- 调用 `alipay.trade.query` 查询商户订单号。
- 校验返回的订单号、金额和商户身份。
- 仅在支付宝明确返回成功交易状态时展示支付成功。
- 未查到或处理中时允许用户稍后重试。

### 异步通知

`POST /api/payments/alipay/notify`

- 使用支付宝公钥进行 RSA2 验签。
- 校验 `app_id`、`seller_id`（已配置时）、商户订单号、金额及交易状态。
- 合法通知返回纯文本 `success`，非法通知返回 `failure`。
- 处理保持幂等。
- 本阶段记录结构化日志；正式交付前改为写入持久化订单库。

## 数据流

1. 用户点击支付。
2. CocoTiny 服务端生成订单号并签名电脑网站支付请求。
3. 用户浏览器跳转支付宝收银台并支付 0.10 元。
4. 支付宝向 CocoTiny 异步通知地址发送支付结果。
5. 支付宝将用户浏览器跳回结果页。
6. 结果页通过 CocoTiny 服务端调用支付宝主动查单。
7. 服务端确认交易状态后向用户展示结果。

异步通知和同步返回到达顺序不固定，主动查单用于首次联调的最终确认。

## 安全约束

- 使用生产 AppID、轮换后的应用私钥、对应应用公钥配置产生的支付宝公钥。
- 所有密钥只存在于 Vercel Production 环境变量和开发者本机，不进入 Git。
- 服务端固定商品和金额。
- 不相信客户端提交的金额或“支付成功”状态。
- 不使用已经在聊天中暴露的旧私钥。
- 日志不得打印私钥、完整签名请求或用户敏感信息。

## 测试与验收

### 自动检查

- TypeScript、Lint 和生产构建通过。
- 支付创建接口缺少配置时返回明确错误。
- 非法商品标识不能创建订单。
- 支付按钮具备防重复提交和失败反馈。
- 通知验签失败时不返回成功。

### 人工生产联调

1. 在 `www.cocotiny.com` 打开资产包支付窗口。
2. 点击支付并成功进入支付宝电脑网站收银台。
3. 核对收款商户、商品说明和金额 0.10 元。
4. 完成真实支付。
5. 返回 CocoTiny 结果页并看到经主动查单确认的成功状态。
6. 在 Vercel Function 日志确认收到且正确处理异步通知。
7. 在支付宝商家账单确认该笔交易。
